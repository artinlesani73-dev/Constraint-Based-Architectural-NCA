# Next proposal: admit larger physical environments separately from resolution

2026-09-24, after MG5. This is a bounded next-work proposal, not an executed scale
study or an authorization for paid training. MG5 closes the known coverage repair:
180/180 development nonpartition cases pass, 45 blocked fail, 179 prior positives
preserved. Do not keep retuning that inspected set merely to improve its score.

The next scientific question is whether the verified procedural baseline remains
useful and affordable as physical environments grow. Preserve the nine families,
D058 building-volume semantics, MG5 recipe and MT1 evaluator. Keep all failures.

1. Audit scene/context construction, serialization, masks and physical measures
   for scene-sized grids. The MG5 runner deliberately reconstructs fixed 32³
   saved cases; it is not a general-size runner. UrbanSceneGenerator uses its
   config grid size, so a larger scene needs a correspondingly explicit context
   config. Do not reinterpret the historical checkpoint as a larger trained model.
   Verify world bounds, occupied cubic metres, interfaces, ground band, padding
   and 2.4 m bulk cubes before scientific generation at a new size.
2. Define two distinct controls. An exact integer translation/embedding into a
   larger grid at 0.8 m/cell checks coordinate and memory handling while preserving
   the same physical site/domain. It is not evidence of larger-site generation.
   New 48³ and conditional 64³ environments at 0.8 m/cell should actually increase
   the declared physical opportunity region. Preserve interface dimensions and
   block scale in metres. Record the resulting domain, quotas and scene identities.
3. Freeze a small finite case list, seeds, requests and source/config hashes before
   outputs. Include a compact case, an offset/obstructed case and a separating-wall
   control. Use a 48-grid admission stage before 64. Record all results, including
   below-target fields, failed checks and unfinished members. Exact numerical
   cases/caps/gates still need to be made runnable before execution; this proposal
   is not a substitute for that preregistration. No coefficient search or rerolls.
4. Profile generation stages and independent evaluation separately. Report route
   search, growth, serialization, resident memory and end-to-end time. Freeze
   cooperative per-case/study time and observed-memory limits before running;
   stop the larger stage when its admission fails. If accounting is the bottleneck,
   propose a separate exact-output optimization with paired regression/timing.
   One concrete candidate is updating cube counts only for origins overlapping
   newly occupied cells, instead of rebuilding whole-volume counts after every
   positive addition. Preserve current-frontier ranking and quota recalculation;
   matching only final scores would be insufficient evidence of equivalence.
   Do not change growth semantics and scale/distribution simultaneously or infer
   cubic runtime scaling from voxel count alone.
5. Finer resolution of the same site is a separate later study. It must rescale
   all building boundaries, entrances/extents, ground thickness and scene-derived
   masks while preserving metres. At 0.4 m/cell the 2.4 m block becomes six cells
   and a 1.6 m interface becomes four cells; simply doubling grid_size is wrong.
   Where a physical boundary cannot be represented exactly, declare rounding and
   its error. Re-audit MT1 threshold/voxelization behavior without relaxing it.

The inspected MG3/MG4 sites are development evidence. A future fresh-site batch
must be frozen separately and analyzed once, preserving failed cases. Scale
controls are not automatically a representative generalization population.

Product promotion can then use a separately identified generator/version while
retaining old replay/import dispatch. Freeze supported sites, size limits and user
tasks before claiming a Studio improvement. The current live page remains MS1.

The learned R2-C pilot stays conditional on a measurable advantage over this
procedural baseline, an admitted continuous objective, explicit GPU allowance
and tested recovery/off-device backup. This plan does not admit paid Colab,
Drive access, new constraints, a new loss, public hosting or repository push.
